# svg3dx 格式规范（草案 0.1）

> 项目概览与授权说明见仓库根目录 [README.zh-CN.md](../README.zh-CN.md) / [README.md](../README.md)。作者：danny许。

## 0. 文档状态

- 本规范为初版草案，命名空间 URI `urn:s3dx:draft:0.1` 为临时值，正式发布时将更换。
- 项目/格式名：`svg3dx`。命名空间前缀：`s3dx`。Logo 标识为 `s3dx`，全称标题为 `svg 3dx`。
- 本草案文件不保证在正式版中可解析。实现应按 URI 识别三维命名空间，不依赖前缀字面量（推荐前缀 `s3dx`）。
- 文件扩展名：沿用 `.svg`，通过根属性 `svg3d="true"` 区分三维内容。正式版可考虑 `.svg3dx`【待定】。

## 1. 文档模型

### 1.1 根元素与开关

- 根元素为 SVG `<svg>`，可包含属性 `svg3d`。
- `svg3d="true"` 启用三维语义；缺省或 `svg3d="false"` 时，所有 `s3dx:*` 元素及其子树按 SVG 未知命名空间元素处理：保留在 DOM 中，不参与求值，不渲染，不影响二维内容。
- `svg3d` 是总开关，优先级高于命名空间：`false` 时即使命名空间正确也忽略。
- 属性名保持 `svg3d`，不随项目名改为 `svg3dx`。语义是“本 SVG 是否包含三维内容”，与项目名解耦。

### 1.2 命名空间

- 三维元素使用命名空间 `urn:s3dx:draft:0.1`，推荐前缀 `s3dx`。
- 三维**元素**进命名空间：`<s3dx:box>`、`<s3dx:cylinder>`、`<s3dx:loop-points>`、`<s3dx:loop-range>`、`<s3dx:bool-union>`、`<s3dx:bool-subtract>`、`<s3dx:bool-intersect>`、`<s3dx:use>`、`<s3dx:model>`、`<s3dx:exp>`。
- **属性**保持无前缀：`href`、`transform`、`mode`、`if`、`ifnot`、`points`、`start`、`end`、`step`、`active`、`svg3d`。
- 标准 SVG 解析器对未知命名空间元素的处理：包含在 DOM 中，不渲染，不进一步处理。本格式依赖此行为实现二维兼容。

### 1.3 二维兼容

- 纯二维内容仅使用 SVG 标准命名空间元素，实例化使用标准 `<use>`，不依赖 `<s3dx:use>`。
- 同一 `<g>` 可同时被标准 `<use>` 和 `<s3dx:use>` 引用：前者在二维渲染中生效，后者在三维求值中生效，互不干扰。
- 本格式不定义三维视口范围。三维几何的投影、观察变换、可见范围由宿主环境决定。

## 2. 参数系统

### 2.1 声明位置

参数以 CSS 自定义属性形式声明，支持三处，优先级从低到高：

1. `<style>` 块内的类规则：`.类名 { --参数名: 值; }`
2. 元素内联 `style` 属性：`style="--参数名: 值;"`
3. 根元素或任意祖先元素的内联 `style` 或类规则（按 DOM 继承）。

**简化子集边界**：只支持类选择器和内联自定义属性。不支持元素选择器、ID 选择器、后代选择器、伪类、`!important`、媒体查询、`@` 规则。超出子集的选择器或声明被忽略，不报错。

### 2.2 引用语法

- 表达式中用 `[名字]` 或 `var(--名字)` 引用参数，两者等价。
- `[名字]` 对应 CSS 自定义属性 `--名字`。

### 2.3 作用域查找顺序

沿 DOM 祖先链向上查找，最近声明者优先，找到即停：

1. 外部传入参数（最高优先级）
2. 自身 `<s3dx:exp>` 的父图元属性
3. 最近祖先 `<g>` 的类规则
4. 更远祖先的类规则或内联 `style`
5. 根元素内联 `style` 或 `:root` 规则
6. 默认值

嵌套 `s3dx:loop-*` 时，内层迭代变量遮蔽外层。

### 2.4 类型解析

- 纯数字字符串 → 数字。
- 空格分隔的数字序列 → 向量。
- `true`/`false` → 布尔。
- 其余 → 字符串。
- 表达式求值时类型不匹配（如字符串用于数值运算）→ 求值错误。

### 2.5 外部传参

- 外部参数是“参数名 → 值”的映射，注入形式由宿主环境决定，规范不绑定（URL query、宿主 API、命令行均可）。
- 优先级最高。命中时直接使用外部值，不再沿 DOM 链查找。
- 不修改 DOM，不改变 CSS 计算值；只在求值阶段作为最高优先级查找结果。
- 未提供的外部参数回退到 DOM 声明；DOM 也没有则求值错误。
- 外部参数键名与表达式中的名字一致，不带 `--`。
- 外部参数值按 2.4 同规则解析类型。

### 2.6 表达式

- 支持运算符：`+ - * /`、比较 `= < > <= >= <>`、括号、逻辑 `and or not`。
- `=` 表示相等比较，不存在赋值。
- XML 属性中含 `<`、`&` 须转义为 `&lt;`、`&amp;`。
- 求值失败（语法错误、未定义参数、类型不匹配）→ 跳过出错元素子树 + 警告。

### 2.7 不依赖 SVG 表现属性的 var()

本格式的参数求值不依赖 SVG 表现属性中的 `var()` 替换。参数值从 `<style>` 规则或内联 `style` 的自定义属性中读取，在 `<s3dx:exp>` 求值阶段由本格式求值器解析。标准 SVG 渲染器对表现属性中 `var()` 的支持差异，不影响本格式的求值结果。

### 2.8 向量在属性值中的展开

- 向量类型参数（如 `[loop.value]`）嵌入属性值时，按空格展开为三个数字。
- 例：`transform="matrix(1,0,0, 0,1,0, 0,0,1, [loop.value])"` 中，`[loop.value]` 展开为 `tx ty tz` 三个数字，结果等价于 `matrix(1,0,0, 0,1,0, 0,0,1, tx,ty,tz)`。
- 表达式结果若为向量，按同样规则按空格展开。
- 如需单独访问分量，可用 `[loop.value.x]`、`[loop.value.y]`、`[loop.value.z]`。
- `points` 属性中的向量序列按同样规则展开。

## 3. 三维图元

### 3.1 通用规则

- 三维图元是 `s3dx:` 命名空间下的元素，作为叶子节点，内部不再嵌套其他三维图元（分组用 `<g>`）。
- 图元属性表以附录形式维护；属性表增补不改变文档格式语法。未在表中列出的属性，实现应忽略并警告。
- 局部坐标 → 父级变换 → 世界坐标的累积规则：图元属性定义的局部几何，先应用图元自身 `transform`，再应用父级 `<g>`/`<s3dx:use>` 的变换。

### 3.2 属性表结构模板

| 图元 | 必选属性 | 可选属性 | 类型 | 默认值 | 坐标系约定 |
|---|---|---|---|---|---|
| `s3dx:box` | Length、Width、Height | LengthVec、WidthVec | 数字/向量 | 【待定】 | 局部 → 父级累积 |
| `s3dx:cylinder` | Diameter、BottomCenterPt、TopCenterPt | — | 数字/点 | — | 同上 |
| `s3dx:sphere` | Radius、Center | — | 数字/点 | — | 同上 |
| … | … | … | … | … | … |

【待定】逐图元填充属性表，包括 `torus`、`squarering`、`wedge`、`prism`、`saddle`、`cone`、`ecccone`、`obliquecylinder`、`cutcylinder`、`ellipsehead`、`rectocircle`、`recsection`、`polylinestretch`、`triangles`。

### 3.3 网格图元

- `s3dx:triangles`：`point` 为顶点坐标序列，`Normal` 为法线序列，`index` 为索引序列。
- 索引基准为 **1-based**。顶点与法线一一对应。索引三元组构成一个三角形。

### 3.4 三维变换

- 三维上下文中 `transform` 使用 12 数矩阵：`matrix(a,b,c, d,e,f, g,h,i, tx,ty,tz)`，前 9 个为 3×3 线性变换，后 3 个为平移。
- 适用范围：`s3dx:*` 元素、`<s3dx:model>` 内元素、`<s3dx:use>`、`<s3dx:loop-*>`、`<s3dx:bool-*>`。
- 二维 SVG 元素的 `transform` 仍按 SVG 标准 6 数解析。按元素是否属于三维上下文判定变换维度。
- 累积顺序：组内变换 → 实例化变换 → 父级变换。

## 4. 组合与布尔

### 4.1 `<g>` 的角色

- `<g>` 承担分组、参数作用域、条件属性（`if`/`ifnot`）。不承载布尔运算。
- 不带 `bool` 的 `<g>`：只做分组和参数作用域，子元素按文档顺序正常累积（等同并集），不改变几何累积语义。

### 4.2 布尔元素

- `s3dx:bool-union`：内部子元素全部并集。
- `s3dx:bool-subtract`：第一个子元素为被减数，后续依次减去。
- `s3dx:bool-intersect`：内部子元素全部求交。
- 内部子元素按文档顺序求值，作用域封闭在元素内部，不与父级已累积结果交互。
- 允许嵌套：内层先求值，结果作为外层一个操作数。
- 空元素：整个元素跳过，不产生几何，不报错。
- 单子元素：该子元素原样输出，不执行布尔运算。
- 操作数可以是 `<s3dx:use>`，布尔作用于其引用的几何体集合，而非元素本身。

## 5. 条件逻辑

### 5.1 挂载点

- `if` / `ifnot` 只能挂在 `<g>` 上。不能挂在三维图元、`<s3dx:use>`、`<s3dx:loop-*>`、`<s3dx:bool-*>` 上。

### 5.2 语义

- `if="条件"`：条件为真时该组参与求值，为假时整个子树跳过。
- `ifnot="条件"`：条件为假时参与，为真时跳过。
- 条件值支持表达式（见 2.6）。
- 同一 `<g>` 上同时出现 `if` 和 `ifnot`：【待定】建议禁止，或规定为“与”。
- 条件求值失败（未定义参数、语法错误）：视为假 + 警告。
- 不支持 `else`；用 `if` + `ifnot` 两个组表达。

## 6. 循环展开

### 6.1 分工

- `<g>` 负责命名分组与条件；`<s3dx:loop-*>` 负责重复展开。
- 循环元素必须位于 `<g>`、`<defs>`、`<s3dx:model>` 内。
- 允许直接写图元、`<s3dx:use>`、嵌套 `loop-*`/`bool-*` 作为子元素。

### 6.2 `s3dx:loop-points`

- 属性 `points`：3 的倍数个数字，每三个构成一个三维点，按点序列逐次迭代。
- 迭代变量：`[loop.index]`（从 0 开始的整数）、`[loop.value]`（当前三维点，向量）。

### 6.3 `s3dx:loop-range`

- 属性 `start`、`end`、`step`（可选，默认 1），支持表达式，求值为数字。
- 按数值序列迭代，含 `start`，不含 `end`。
- 迭代变量：`[loop.index]`、`[loop.value]`（当前数值）。

### 6.4 通用规则

- 迭代变量固定，不提供 `var` 自定义。
- 嵌套循环：内层 `[loop.index]`/`[loop.value]` 遮蔽外层，最近一层优先。
- 展开时机：参数求值之后、条件求值之前。
- 未知 `s3dx:loop-*` 元素：按未知元素跳过整个子树，不报错。
- 可扩展性：`loop-*` 是开放命名空间，后续版本可增加新模式，实现遇到不认识的 `loop-*` 应跳过而非报错。
- 展开后的多个副本，在布尔累积中按文档顺序独立参与。

## 7. 模型与显示

### 7.1 `<s3dx:model>`

- 属性：`id`（必选）、`mode`（必选）、`transform`（可选，12 数三维矩阵）、`active`（可选，布尔）。
- `mode` 取值：`solid`（着色实体）、`wireframe`（线框）、`hidden-line`（隐藏线）。【待定】是否需要 `points` 等。
- 子元素：一个或多个 `<s3dx:use>`，按文档顺序指定显示内容。
- 不设 `visible` 属性；显示范围完全由子 `<s3dx:use>` 决定。
- 语义：定义一种显示配置，不定义相机或投影。
- 同一 `<g>` 可被多个模型引用，几何只求值一次，渲染按模型配置分别进行。

### 7.2 多模型切换

- 文件可定义多个 `<s3dx:model>`。
- 默认生效模型：`active="true"` 标记者；若无标记，取文档中第一个 `<s3dx:model>`。
- 外部参数可覆盖（如传入 `model=wireframe-view`，按 `id` 匹配切换）。

### 7.3 与标准 `<view>` 的关系

- 标准 SVG `<view>` 与 `<s3dx:model>` 语义独立，不得互相替代。标准 `<view>` 用于画布视口覆盖，`<s3dx:model>` 用于三维渲染模式。

## 8. `<s3dx:use>`

- 属性：`href`（必选，引用 `<g id="...">`）、`transform`（可选，12 数三维矩阵）。
- 不设 `x`/`y`；三维平移用 `transform` 的 `tx/ty/tz`。
- 仅用于三维上下文；标准 `<use>` 仅用于二维内容，两者不得混用。
- `<s3dx:use>` 引用纯二维 `<g>`（只含二维元素）时：跳过 + 警告。
- 变换累积：被引用组自身 `transform` → `<s3dx:use>` 的 `transform` → 父级变换。

## 9. 求值模型

### 9.1 阶段顺序

1. 解析文档树
2. 建立参数作用域
3. 解析外部参数
4. 展开 `loop-*`（求值 `loop-range` 参数）
5. 求值 `if`/`ifnot`（展开后每个副本独立判断）
6. 求值 `<s3dx:exp>` 与表达式
7. 生成几何操作图
8. 内核求值，得到几何体集合
9. 按 `<s3dx:model>` 的 `mode` 和子 `<s3dx:use>` 过滤/渲染

关键：`<s3dx:model>` 不参与几何求值，只在渲染阶段起作用；几何只求值一次，多模型共享。

### 9.2 错误处理

- 求值错误范围：表达式语法错误、未定义参数引用、类型不匹配、`loop-range` 参数求值后非数字。
- 处理方式：跳过出错元素及其子树，记录警告。警告形式由宿主决定，规范不绑定。
- 文档级致命错误（XML 不合法、根元素缺失）：按 XML/SVG 既有规则处理，不属于本格式“跳过”范畴。
- “跳过+警告”是推荐行为，实现可选择更严格的报错模式，但不属于合规要求。

### 9.3 确定性与精度

- 同一文件在不同内核上求值，拓扑等价性由内核保证，本格式不规定数值精度。
- `<defs>` 中未被任何 `<s3dx:model>` 可达的实例化链引用的定义，不求值。
