# svg3dx 路线图

> 项目概览见 [README.zh-CN.md](../README.zh-CN.md)。  
> **语言**：本文件为**中文版**。English edition: [roadmap.en.md](./roadmap.en.md)。  
> 这里的版本号是**规范草案**号。svg3dx-core、svg3dx-viewer、svg3dx-studio 各自使用语义化版本，并注明所跟随的草案。

## 版本一览

| 草案 | 角色 | 状态 |
|------|------|------|
| **0.1** | 初步草案（稳定轨） | 已发布 |
| **0.2** | 特性试水 | 进行中，不稳定 |
| **0.3** | 厂商标准引入 | 计划 |
| **0.4** | 工程试点 | 计划 |
| **0.5** | 试点修订 | 计划 |
| **0.6** | 一致性与可检验 | 计划 |
| **0.7** | 补齐试点点名的构造缺口 | 计划 |
| **0.8** | 特性冻结 | 计划 |
| **0.9** | 发布候选 | 计划 |
| **1.0** | 标准发布 | 计划 |

## 草案号与命名空间

- **0.1** 稳定轨使用 `urn:s3dx:draft:0.1`，保持可读写到 1.0 迁移完成。
- **0.2** 试水期间沿用 `urn:s3dx:draft:0.2`。试做的能力在本草案正文里增删，试水期间不另开 URI。
- 试水结束、进入 **0.3** 时，把「留下 / 改写后留下 / 撤掉」写进该版迁移说明。作者必须改写文件内容时才新开 URI，并写明上一轨要兼读到何时。
- **0.4** 试点期间不换 URI。冻结的是试水结束后的核心。
- **1.0** 使用永久命名空间 URI，替换 `urn:s3dx:draft:*`。

## 0.1 初步草案

已发布，稳定轨。

覆盖参数、图元、逻辑、布尔、材质、显示、glTF，以及用 SVG `<metadata>` 携带外挂命名空间。本轨不再增加新图元。规范：[草案 0.1](./svg3dx-spec-draft-0.1.md)。

## 0.2 特性试水

进行中。本版尽量试做各种特性，是较不稳定的一个版本。

已经写入的能力与后续试做的能力都留在这一版：允许改写法、收窄范围，或整段撤掉。只实现 0.1 的工具继续按稳定轨工作。读取 0.2 的实现应预期正文在试水结束前还会变。规范：[草案 0.2](./svg3dx-spec-draft-0.2.md)。

每项试水带样例，并事先写明撤掉条件。用现有图元就能表达，或得不出稳定语义的，从 0.2 去掉。试水期间新开的项目，先补进下表再写入规范。

### 已写入

- 定位点 `point` 与活引用 `ref(#id)`
- 动画子集 `animate` / `animateTransform`（`from` / `to`）

### 继续试做

| 试水 | 要验证的问题 |
|------|----------------|
| 动画再往前走一步（`values` / `keyTimes`） | 机构演示是否只靠 `from` / `to` 就够 |
| 样条、螺旋、优弧、截面曲线命令 | 真实轮廓是否会被折线逼成错误配方 |
| 扫掠起始方位 `refDir`、开放回转体是否封盖 | 构造结果是否会因实现不同而分叉 |
| 圆角与倒角中先选一个 | 修饰算子进入核心，还是继续用布尔 / `gltf` 近似 |
| 用现有注册表再走一遍厂商剖面 | 外挂命名空间能否挂上企业字段。字段表本身留到 0.3 |

贴图与完整 PBR、相机、导出 IFC、永久命名空间 URI 不进入本轮试水。它们不改变配方怎么写。

### 结束条件

0.2 关闭时留下一份清单，每项只有三种结论：留在核心、改写后留下、撤掉。清单闭合之后才进入 0.3。自 0.3 起只接收这份清单里留下的能力。

## 0.3 厂商标准引入

按试水结论发布厂商剖面规则。引入的是已经留在核心里的文档模型。

规范第 9 节已有 `<metadata>` 容器、关联方式和注册表。本版把「别人能照着发布一份剖面」写成可执行规则：

- 厂商命名空间 URI 如何取值、如何带版本，以及 `draft` / `stable` 各表示什么。
- 剖面以 `namespaces/<厂商>/` 下的可机读定义发布，并在 `registry.xml` 登记。
- 核心求值保留外挂子树；解释字段语义由宿主负责。
- 行业短名（封头、马鞍三通等）继续留在核心之外，用 `loft`、`revolve`、布尔表达。
- 往返和 optimize 保留外挂节点，并带有对应样例。

真实企业的字段表在 0.4 产生，版本跟着该厂商自己的命名空间，不占用核心草案号。

## 0.4 工程试点

选一到两家企业、一类构件（设备壳体加管嘴，或一段参数化管件）。试点文件只使用试水结束后留下的核心。试点期间草案文本冻结，问题只记入清单。

验收：

1. 对方能用 svg3dx 写出现有参数化构件的配方。
2. 求值结果与原构件在拓扑上可对照。
3. 厂商属性能挂在 `<metadata>` 上，保存再打开不丢。

清单里每条归入三类：必须进 0.5、可以延期、属于厂商剖面。

## 0.5 试点修订

只处理 0.4 的清单。每条结论写成采纳、延期或留在厂商剖面。0.2 已撤掉的特性留在撤掉清单。

同时写下本轮之后保持不动的决定：SVG 兼容、CSS 自定义属性传参、与内核解耦、不定义相机、不取代 IFC。修订附带迁移说明。待定项分成「1.0 前必须决定」和「1.0 后」。

## 0.6 一致性与可检验

建立正例、反例、警告三类测试集。写明求值器必须实现什么，以及宿主可以不做动画时钟和厂商语义。把 `.svg3dx` 与 `.svg3dxz` 从待定改为规定。

## 0.7 构造缺口

只补试点证明「现有图元表达不了」的构造。能用现有 `loft` 或布尔表达的，保持在核心外。若试点没有此类缺口，本草案无图元变更，版本号仍然保留。

## 0.8 特性冻结

不再增加图元。正式命名空间 URI 的形式在本版定稿，到 1.0 才切换。动画与材质维持试水结束后留下的范围。至少存在一条 core 之外的只读往返。

## 0.9 发布候选

只修改歧义、迁移说明、中英对照和名词表。向试点企业与仓库公开征集一轮意见；意见只用于文字和明显错误。

## 1.0 标准发布

同时满足以下条件后，换用永久命名空间 URI，替换 `urn:s3dx:draft:*`：

- 核心图元、参数、逻辑、布尔、试水后留下的动画子集、厂商引入规则都已冻结。
- 0.6 的测试集通过。
- 0.8 的外部往返存在。
- 0.5 标成「1.0 前必须决定」的待定项都已关闭，或已写入延期清单。
- 写明实现还要读取哪些旧草案 URI，以及读到何时。

厂商剖面在 1.0 之后按各自的 URI 继续演进，不随核心版本绑定。

## 1.0 之后

下列事项不作为 1.0 的前置条件：抽壳；贴图与完整 PBR；试水未留下的动画能力（事件触发、`animateMotion` 等）；多内核数值互认；导出 IFC。圆角与倒角以 0.2 的试水结论为准，未留下的不进入 1.0。

重新考虑这些事项时，需要新的使用证据。
